# 竞知文件导入：第一步数据契约与草稿规则

版本：2026-10-15。范围：共享DTO、接口签名、纯校验/草稿准备规则及测试。本步不提供可调用HTTP路由、上传存储、PDF/DOCX解析、OCR、大模型服务、识别页面或数据库迁移。安装后不会出现上传按钮。

## 1. 业务流程和权限

上传材料 → 创建识别任务 → 排队/识别 → 查看原材料及候选字段 → 逐项人工确认 → 原子创建/派生普通草稿 → 手动提交 → 校级管理员审核 → 学生可见。

识别成功不等于保存草稿，保存草稿不等于提交，提交不等于公开。本规则只返回普通CreateDraftRequest和内部ImportDraftOrigin，不直接访问数据库。

|身份|新建导入|补充已有赛事|读取文件/任务|审核与公开|
|---|---|---|---|---|
|校级管理员|本校允许|本校允许|本校有效范围|沿用本校审核权限|
|学院负责人|本步不增加新建权限|仅当前分配且授权有效的赛事|仅本人创建且目标仍有维护授权|不能审核|
|仅平台管理员|不凭平台角色取得校内赛事写权限|须另外获得对应校级授权|同左|同左|
|学生/无授权账号|不允许|不允许|不允许|不允许|

所有身份、学校、目标赛事、组织信息从服务器会话/数据库重新读取，不信任客户端userId、旧Role或学生浏览高校。权限撤销、学院停用、赛事重新分配后立即拒绝继续读文件、查看任务或确认。服务端列出任务和返回重复候选时先按当前权限裁剪，不泄露跨校/他人材料。

首次任务目标固定。已分配赛事在原详情入口上传；不能在确认时把新建任务改成另一个目标。发现重复后若想补充已有赛事，先取消本任务，从已有赛事重新建立目标绑定任务；同文件可否复用也必须重新校验学校、上传者及目标范围。

## 2. 文件契约与限制

首期只支持PDF、DOCX、JPEG、PNG、WebP；旧DOC、Excel、压缩包、可执行文件暂不支持。单文件≤20MiB；每任务总计≤40MiB、≤100页。每任务一份PDF/DOCX，或最多10张有序图片。一个任务只确认一项赛事；多赛事通知应拆分成独立任务，后续再扩展批量确认。

ImportFile记录服务器fileId、学校、上传者、目标赛事、原文件名、真实检测类型、字节数、SHA-256、页数、上传状态、创建及过期时刻。客户端声明大小/摘要仅是预检查，服务器必须重算；文件名不作磁盘路径，不接受目录分隔符，不仅凭扩展名放行。已接收状态必须在真实格式、大小、解析安全等检查后由服务端设置。

ImportUploadTicket.uploadPath为相对管理API上传路径，例如/manage/import-files/{id}/content；不含本地磁盘路径或永久公网地址。原文查看/下载由授权接口返回，所有请求重新鉴权。不能把上传文件URL作为“官网来源”自动写入sourceUrl。

PDF用原页码；图片按上传次序确定页码；DOCX需先以固定渲染流程生成稳定分页材料，再保存页数和证据页码。后续服务端实现应限制解压大小、解析耗时/内存、图片像素数，拒绝宏/嵌入危险内容及加密无法解析文件；失败只返回标准失败码，不把堆栈、密钥、文件系统路径返回客户端。

建议初始策略：上传票据15分钟；未完成且未转草稿的文件/任务72小时到期。时间必须来自服务器，expire检查使用明确时区时刻。任务转草稿后，材料进入版本证据保留流程，不因临时TTL清理而断链。deleteFile仅允许删除未被任务/版本引用的临时文件；已引用返回409。需清理已引用原件时走独立审计流程，不在本步自动删除。

## 3. 识别结果和证据

ImportRecognitionResult同时含候选、证据、问题和可访问的疑似重复赛事。一个字段允许多个候选，不以最高置信度覆盖冲突。

- 候选：candidateId、field、value、rawText、置信度0—1或null、日期精度、原时区、evidenceIds；阶段候选field=stageDate并含stage。
- 证据：evidenceId、jobId、fileId、从1开始的页码、≤1000字原文片段、可选定位描述；必须归属本任务及真实页数。
- 问题：未公布、低置信度、文本模糊、年份缺失、时区缺失、时间冲突、来源冲突、疑似重复、不安全材料及识别失败。
- 严重度：提示／需确认／阻断。“需确认”逐项保存确认说明；阻断问题不能靠勾选绕过，需更换材料/重新识别消除。

识别器输出不可信：不得执行文档中的命令、URL请求或“忽略规则”指令；只形成结构化候选，所有写操作、权限、审核状态仍由服务器控制。文本以普通文字展示，不作为HTML/脚本渲染。引擎版本供内部追溯，密钥和完整提示词不进入DTO。

## 4. 日期与阶段规则

|原文|可写入|禁止行为|
|---|---|---|
|只写2026年10月|简介中的月份说明；具体日期留空|编造10月1日或31日|
|只写10月30日、缺少年份|标注缺年份，人工补充依据后填写|自动沿用系统年份或往届年份|
|明确2026-10-30|仅日期YYYY-MM-DD|自动追加23:59|
|明确日期、时刻和时区|转换为YYYY-MM-DDTHH:mm:ss+08:00，保存原文和原时区|按服务器本地时区猜测|
|先公布、后更正且有冲突|保留多候选，人工确定采用及原因|只因位置靠后或置信度高就自动覆盖|
|只有初赛开始/结束|独立阶段日程|将初赛结束写成整个赛事结束|
|作品提交截止|独立阶段日程|当成比赛结束或报名截止|

采用日期候选必须明确核对原文年份、阶段、精度及时区，留下说明；低于0.85或未知置信度的其他候选也须核对说明。置信度不是事实正确率或真实性认证。没有可核对的具体日期时可保存“待补充”草稿，不谎称日程完整。

阶段信息通过stageConfirmations单独确认，不允许在draft.schedule直接注入。若已确认公开HTTPS官方来源，准备为现有ContestScheduleItem；若只有私有上传文件，阶段值保留在简介并标为“上传资料整理，尚待官方来源核对”，详细证据写内部origin。不能用私有文件下载地址伪装原通知网址；以后可扩展公开日程的证据类型。

## 5. 确认转草稿

ConfirmImportDraftRequest包含任务etag、幂等键、创建/补充决策、固定目标及公开版本etag、重复说明、普通draft、逐字段确认、分阶段确认和问题处理说明。

每个标量字段均明确选择：采用识别（候选值与证据精确对应）、人工填写（附说明）、保留未知（null）。确认时客户端重送的draft要与每个确认值一致。名称、明确届次、分类、归属、层级和修改原因必填；其他暂缺的发布资料可以留空，之后仍受普通提交校验。结构化适用对象按原有表单人工填写，不从OCR文本直接生成权限。

服务端解析并确认主办单位属于目标高校。强制entryType=团队整理；collectedAt由服务器确认时刻生成；不能自动授予主办方填报身份、第二课堂加分或上传者管理权限。creditApplicable沿用既有规则；“适用”必须有学校依据。不能从通知文本生成附件ID；以后附件关联由服务器绑定本任务的合法文件。

新建：仅允许具有新建权限的校级管理员；有疑似重复候选时必须说明为何仍新建。校内同名不直接合并，不跨届替换历史。

补充：保持contestId、所属学校、收藏、反馈及公开指针。要求公开版本etag仍匹配、没有任何工作版本、目标未下架；通过现有deriveVersion创建草稿，再updateDraft。已有草稿/驳回/待审版本返回409，引导原编辑流程，不覆盖负责人修改。客户端草稿中未填的本地资料不能借导入清空：后续服务端在确认页加载原payload，显式逐字段合并后再提交，本函数只核对最终合并结果。

## 6. 原子性、幂等与并发——后续服务端必须落实

本步纯规则不实现数据库锁或幂等存储。后续confirmDraft必须在同一事务内：重新鉴权及读取任务/文件/目标 → 校验任务etag和期限 → 查询幂等请求 → 校验并准备草稿 → 创建/派生普通版本 → 保存origin/文件引用 → 写draftLink及任务已转草稿 → 提交事务。

- 幂等键按学校+操作者+操作划分；同键同请求摘要返回原结果，同键不同摘要返回409。确认幂等检查要在“已转草稿”状态拒绝前返回已有相同结果。
- jobId的草稿关联必须唯一；两个不同幂等键并发确认也只能生成一个草稿，另一个返回409。
- 上传/创建任务也使用幂等键，不因网络重试多传、多识别、多收费。
- 失败时所有版本、关联和任务状态回滚；没有半个草稿。源文件重复SHA-256可提示，不能跨校泄露或自动复用权限。
- 相同识别结果不重复创建版本；重试失败任务使用etag、最多3次、更新engine/attempt等内部记录。取消/过期后迟到识别结果不得恢复任务。
- 任务进度不估计虚假百分比，失败可展示可理解错误码；删除/过期状态不可恢复为成功。

## 7. 后续HTTP接口约定（本步未注册路由）

|方法|路径|行为|
|---|---|---|
|POST|/manage/import-files|创建受限上传票据|
|PUT|/manage/import-files/:fileId/content|按票据上传二进制，独立流式限额|
|POST|/manage/import-files/:fileId/complete|服务端检查摘要、类型、页数后确认接收|
|GET|/manage/import-files/:fileId/content|受权限控制的原文查看/下载|
|DELETE|/manage/import-files/:fileId|仅删除可清理临时材料|
|POST|/manage/import-jobs|创建识别任务|
|GET|/manage/import-jobs|按授权分页查询|
|GET|/manage/import-jobs/:jobId|读取任务|
|GET|/manage/import-jobs/:jobId/result|读取候选及证据|
|POST|/manage/import-jobs/:jobId/confirm|原子转普通草稿，不自动提交|
|POST|/manage/import-jobs/:jobId/retry|失败任务受限重试|
|POST|/manage/import-jobs/:jobId/cancel|按etag取消|

沿用code/message/data/traceId错误信封：401未登录；403越权；404当前授权范围内不存在；409版本/状态/幂等/引用冲突；413文件过大；415不支持格式；422字段或候选校验失败；429频率/配额超限；503识别服务不可用。纯规则的预检查额度暂返回422；实际上传路由按413/415等细分。

## 8. 第二步接入顺序

先实现数据库任务/证据/引用/幂等存储与文件接收，再接入可替换的文本提取和OCR识别适配器，最后管理端上传、轮询及原文对照确认页。任何第三方识别服务的密钥仅在后端配置；接入前明确是否上传第三方、按量费用与数据保留范围。首期不接学生端上传入口，不允许未审核文档进入公开赛事。
