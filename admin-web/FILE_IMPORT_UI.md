# 文件导入管理页面与验收

## 使用入口

管理端登录后选择当前工作高校，点击“文件导入”。校级管理员可以选择新建赛事或补充本校已有赛事；学院负责人只能补充已分配且仍有授权的公开赛事。平台管理员也需要相应学校的校级授权，平台身份本身不能越过业务权限。

已有赛事也可从“赛事维护 / 目录编辑”列表的“从文件补充”进入。目标必须已公开、未下架、没有工作草稿/待审核版本。不覆盖待处理修改，任务绑定的目标不能临时切换。

## 上传和识别

1. 选择一份PDF/DOCX，或同一赛事最多10张照片；单份20MiB、合计40MiB。材料不应同时包含多项待新建赛事。
2. 点击“上传并检查材料”。真实格式、摘要和限额均由服务端复核，扩展名不能绕过校验。部分上传失败可继续，放弃时使用“清理已选材料”。
3. 本地文字层提取不调用外部服务。图片/扫描页需要后端配置视觉OCR；未配置时任务明确失败。配置启用时，必须逐任务勾选可发送材料。清理个人无关信息，OCR账户费用由自行配置的服务决定。
4. 创建识别任务后，列表保留排队、识别、待确认、失败、已取消、已转草稿状态。当前任务自动刷新，离开后仍在后台处理。失败最多手动尝试3次；不会无提示自动重复外部调用。
5. 使用localhost或HTTPS打开管理端。浏览器在普通局域网HTTP地址上可能不提供摘要校验所需的安全上下文，会明确提示切换地址。学生端连手机/模拟器的方式不受此限制影响。

## 对照原件与确认

- 待确认页面左侧是字段/阶段，右侧是原材料。DOCX显示规范化文字页，不冒充Word打印页。PDF预览受浏览器限制时可下载原件；照片可直接查看。
- “采用候选”“人工填写”“保留未知”逐项选择。低置信度、人工输入、日期都需说明核对依据。候选不是认证结论。
- 非日期项可以在逐项对照后填写共同说明、勾选声明再记录核对。日期、阶段仍分别确认，必填字段不能保留未知。
- ISO日期格式为2026-10-30；原文精确到时间才填2026-10-30T20:00:00+08:00。只写月份、缺年份、缺时区或存在歧义时，保留未知并说明，不能用示例替代实际赛事日期。
- 初赛、决赛、作品/论文截止分别列为阶段。初赛结束、作品截止不等于整项赛事结束。没有公开HTTPS来源的上传资料只能形成待核对说明，不会伪装成官方公开日程。
- 疑似重复项不自动合并。确实是已有赛事，应取消此新建任务，再以已有赛事为固定目标重新上传。确认独立新建时须说明区别。
- 原赛事的结构化参赛范围、第二课堂信息和附件保留；新赛事第二课堂默认待确认。表单只补充适用对象说明，不从识别文字自动授予学分。
- 勾选最终核对后“保存为赛事草稿”。网络失败保留当前输入，相同内容重试不会生成第二份草稿。刷新/离开会丢失尚未保存的人工输入，系统会提醒；已保存任务和草稿仍保留。

## 提交与校级审核

保存后点击“前往赛事维护”，补全发布资料，再提交。负责人没有审核权限。校级管理员在赛事审核详情中查看上传原件、识别片段、逐字段/阶段/问题确认记录，然后按既有流程决定通过或驳回。来源加载失败时阻止直接通过，需重新打开恢复后再审。

上传原件只通过带身份的私有接口访问。学生端不展示私有文件链接；账号停用、负责人授权撤销后即不能继续读取。已关联草稿的材料会保留供审核核对，数据库与原文件需要一并备份。

## 建议本机验收顺序

1. 管理员上传无敏感信息、文字清晰的一份赛事DOCX/PDF，状态变为待确认；刷新页面后任务仍在。
2. 检查每个日期和分阶段候选。先不勾选核对，确认不能直接保存；月份不应补成具体某天。
3. 对照原件补齐必填项，确认后保存。待审核前学生端不可见；赛事维护可打开草稿，当前任务显示已转草稿，重读不生成第二份。
4. 提交并用校级管理员查看原材料和确认记录；审核通过才在学生端出现。
5. 从已有赛事发起补充，修改说明后保存草稿，学生端仍显示原内容，审核后才变化；原收藏和反馈仍关联原ID。
6. 负责人仅能选择已分配赛事、不能新建或审核；撤销授权后不能读取结果、原材料或转草稿。学生账号不能进入上传与材料接口。
7. 未配置OCR时图片任务明确失败；配置自己的服务并授权外发后，再用测试照片验收真实识别。仍逐字段核对，不将OCR输出作为事实直接发布。
8. 取消任务、停止服务再恢复、重新登录，确认已有材料/任务/草稿保留；保存前的未持久化表单输入不承诺恢复。

## 本轮验证边界

管理端生产构建、后端接口/事务/模型/二进制上传下载回归、原生服务TypeScript回归和已知ArkTS非UI语法检查已执行。没有在你的Windows、DevEco SDK、浏览器或真实收费OCR账户运行本轮验收；本机页面布局、PDF预览、安装和真实照片识别仍按上面步骤验收。已有Vite大包警告不阻止构建，后续可单独优化。
